# ADR-0001: Use Modular Monolith as the Initial Architecture

**Status:** Accepted

## Context

FlowHub is a new project that is expected to grow over time. In the future, it may evolve into a Microservices architecture, but at the current stage the business requirements and system complexity do not justify the operational cost of Microservices.

## Decision

We decided to start with a Modular Monolith architecture.

Each business module will have clear boundaries and its own internal Clean Architecture. This allows us to keep the application simple while preserving the ability to extract modules into Microservices when there is a real business need.

## Alternatives Considered

### Microservices

Rejected because the project does not currently require independent deployment, independent scaling, or multiple development teams. The additional complexity would not provide enough value at this stage.

## Consequences

### Positive

- Simpler development experience.
- Easier deployment.
- Lower operational complexity.
- Clear module boundaries.
- Easier future migration to Microservices.

### Negative

- The application is deployed as a single unit.
- Modules cannot be deployed or scaled independently.
